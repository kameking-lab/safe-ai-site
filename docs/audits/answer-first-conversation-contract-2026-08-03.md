# 安衛法AI Answer-first会話契約（2026-08-03 JST）

## 適用経路

`/chatbot`のJSON、SSE、AI OFF、retrieval-only、no-script、ホームからの同一タブ引継ぎ、follow-up、legacy `/api/chat`へ適用する。質問分類は内部処理だけに使い、分類画面や選択肢だけの応答を利用者へ見せない。

## 通常応答

すべての通常応答は次を満たす。

1. `substantiveAnswer`: 与えられた情報で成立する最適な暫定回答。空文字は禁止。
2. `assumptions`: 暫定回答の前提。最大3件。
3. `conditions`: 法的結論が変わる主要条件。最大3件。
4. `citations`: 本文の法的主張に対応する確認済み一次資料。該当根拠がないときは空配列とし、断定しない。
5. `clarificationQuestion`: 不要なら`null`、必要でも最後に1件だけ。何を絞るための質問かを示す。
6. `quickReplies`: 回答後にだけ表示するcompactな候補。最大3件で、自由入力を妨げない。

表示順は「結論2〜4文 → 条件で変わる点最大3件 → 必要時の確認質問1件 → compact quick reply最大3件 → 折りたたみ根拠 → 次にできること最大2件」とする。コピー等を含む回答操作全体も最大3件とする。

runtime finalizerは、`substantiveAnswer`が空で確認質問だけになるpayloadを、理由と次に入力すべき内容を持つ説明付きfallbackへ補正する。通常経路でそのfallbackへ到達した場合は契約テストと評価をfailureにする。確認質問の連続、chipだけの応答、複数候補を理由にした回答放棄もfailureとする。

## 例外

緊急、PII遮断、完全に意味を特定できない入力だけは通常法令回答を行わない。その場合も、回答できない理由と利用者が次に入力すべき内容を1文で示す。緊急は119等の案内を優先し、PIIは外部送信・保存を行わない。

## 会話文脈

同一タブのmemory-onlyで、作業種類、設備、高さ、荷重、電圧区分、役割、資格区分、対象日、確認済み選択肢だけを保持する。短いfollow-upは直前の安全な条件へ結合する。たとえば「電気作業の資格は？」の後の「作業主任者」は「電気作業で作業主任者の選任が必要か」と解釈する。

氏名、会社名、現場名、住所、電話、メール、社員番号、健康情報、生の会話履歴は条件へ取り込まず、URL、Web Storage、Analytics、RUM、consoleへ永続化しない。ホーム引継ぎも同一タブの一回限りとする。

## 根拠契約

法的主張は本文の番号引用と、同じ番号の法令名、条・項・号、施行状態、該当箇所、公式原文を対応させる。未確認・隔離中の通達、質問と無関係な検索候補、将来施行条文を現在の根拠へ混在させない。確認済み一次資料で直接支えられない場合は保留し、確認すべき資料または条件を示す。

## 固定回帰条件

- 通常質問のanswer-first率・substantive answer率: 100%
- pure clarification率: 0%
- follow-up文脈保持率: 100%
- 確認質問最大1件、quick reply最大3件、回答操作最大3件
- 無関係カテゴリ飛躍、引用なし法的断定、危険な見逃し: 0
- PII外部送信: 0、緊急時通常回答: 0
